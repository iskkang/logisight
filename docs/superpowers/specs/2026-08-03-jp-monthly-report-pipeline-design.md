# 일본판 월간 리포트 파이프라인 설계

**작성일**: 2026-08-03
**대상**: `generators/jp-report/` (신설)
**전제**: 일본 사이트는 한국 사이트와 분리 운영. 한국 파이프라인 코드는 건드리지 않는다.

---

## 1. 배경

일본 데이터 수집은 완료됐다(23,940행).

| 축 | 테이블 | 지연 | 최신 |
|---|---|---|---|
| 운임 | `jp_price_indices` | 1개월 | 2026-06 |
| 무역(국가) | `jp_trade_stats` | 1.5개월 | 2026-06 |
| 무역(품목×국가) | `jp_trade_by_commodity` | 1.5개월 | 2026-06 |
| 항만 | `port_throughput` (country='JP') | 3개월(속보) | 2026-05 |

**확보 데이터가 전부 월차다.** 주간 리포트는 뉴스 기반이 될 수밖에 없으므로 월간부터 만든다.

### 샘플 리포트에서 확인된 실패 3종

LLM으로 실제 리포트를 한 편 생성해 확인했다. 문체는 일본 업계지 수준이었으나:

1. **수치 오표현** — 지수 차이 73포인트를 "15ポイント超の開き"로 서술(전년비 차이 15.4%p와 혼동). 업계지에서 즉시 지적당하는 종류.
2. **근거 없는 추측** — "港湾間での取扱シフトが進んでいる可能性". 프롬프트에 추측 금지를 넣었는데도 발생.
3. **가장 강한 앵글 누락** — 국제항공화물 계약통화 지수 98.1(100 미만 = 달러 기준 운임은 2020년 수준 복귀)을 언급하지 않음.

이 세 가지가 검수 설계의 근거다. 각각 잡는 방법이 다르다.

## 2. 구조

```
research/  →  write/  →  verify/  ⇄ (REVISE → write 되돌림, 최대 2회)
                            │ PASS
                            ▼
                        image/  →  assemble/  →  publish
                            │ 2회 실패
                            ▼
                     발행 보류 + 알림
```

발행은 **완전 자동**(사람 승인 게이트 없음). 단 검증 실패 시에는 **발행하지 않고 멈춘다(fail-closed)**.
자동화의 의미는 사람이 승인 버튼을 누르지 않는 것이지, 틀린 수치를 내보내는 것이 아니다.

---

## 3. 단계별 정의

### ① researcher

DB에서 축별 팩트시트를 조립한다. 축마다 빌더 하나: `sppi.js` / `trade.js` / `port.js` / `commodity.js`.

출력은 **구조화 JSON**이며 모든 수치에 출처·기준월·단위가 붙는다.

두 가지를 반드시 명시한다:

- **기간 불일치** — 무역은 6월, 항만은 5월이다. 팩트시트가 이를 드러내야 writer가 "6월 리포트"에 5월 수치를 섞으면서 그 사실을 감추지 않는다.
- **결측** — 환율 시계열 없음, 荷動き(항로별 물동량) 없음 등. 없는 것을 아는 상태로 써야 한다.

PostgREST 기본 반환 한도(1,000행)에 걸리므로 집계 조회는 반드시 페이지네이션한다.
(팩트시트 검증 중 실제로 이 함정에 걸려 품목 합계가 55%만 집계된 적이 있다.)

### ② writer

`sections.config.js`(일본판)에 섹션 정의 + `focus` 프롬프트. 한국 파이프라인과 같은 선언형 패턴.

주입물:
- 일본어 스타일 가이드 (기존 한국 가이드 번안)
- 구글 JP SEO 가이드 (기존 `generators/web/seo-guide.md` 335줄 중 네이버 부분 제외 후 재작성)
- researcher가 만든 팩트시트

**팩트시트에 있는 수치만 사용**한다.

### ③ verifier — 게이트

**(a) 결정적 수치 검증**
본문에서 숫자를 추출해 팩트시트와 대조한다. 팩트시트에 없는 수치가 나오면 REVISE.
코드로 하므로 놓치지 않는다. 샘플의 "15ポイント"는 여기서 잡힌다.

**(b) LLM 편집 검수**
근거 없는 추측, 출처 없는 단정, 데이터 특성 누락(예: 계약통화 지수가 100 미만인데 언급 없음)을 판정.
판정은 PASS / REVISE / REJECT 3단.

REVISE면 지적사항을 붙여 writer로 되돌린다. **최대 2회**. 그래도 실패하면 발행하지 않고 알린다.

### ④ image maker

데이터 기반 차트 + OG 이미지. 기존 `generators/report/lib/chart-data.js` 재사용.

샘플 기준으로 바로 나오는 차트 둘:
- 외항화물 운임 엔 베이스 vs 계약통화 베이스 대비
- 주요 6항 컨테이너 전년동월비

### ⑤ assembler

마크다운 → HTML/PDF, SEO 메타(title·description·JSON-LD `Article`), 발행.
기존 `generators/lib/publish-report.js`·`monthly-report-pdf.js` 유틸 재사용.

---

## 5. 검증 기준

- 팩트시트 빌더: 각 축의 집계가 DB 원본 합계와 일치(무결성 대조)
- verifier(a): 팩트시트에 없는 수치를 본문에 넣은 초안을 REVISE로 판정
- verifier(b): 추측 문장이 든 초안을 REVISE로 판정
- 파이프라인: 2회 REVISE 후에도 실패하면 발행 호출이 일어나지 않음
- 기존 한국 리포트 테스트 회귀 없음
