# Report Authoring Standard (Logisight)

생성형 산출물(전망·브리프·리포트) 작성 공통 기준. Phase 6 전망 파이프라인(`generators/web/generate-forecasts.js`)과 향후 리포트 생성기에 공통 적용한다.

## 1. 독자 단위 번역 규칙 (필수)

모든 전망·분석에는 **3단 변환**을 반드시 포함한다. 지표를 화주·포워더가 바로 행동에 옮길 수 있는 언어로 옮기는 것이 목적이다.

1. **지수 변화** — 무슨 지표가 얼마나 움직였나 (예: SCFI MoM +6.0%)
2. **FEU/kg당 비용·리드타임 영향** — 그게 단가/리드타임에 어떤 의미인가 (예: 유럽행 FEU 단가 상승 압력, 리드타임 +N일 가능성)
3. **권장 행동 1개** — 그래서 무엇을 하면 되나 (예: 7월 계약분 부킹 타이밍 앞당겨 검토)

전망 레코드에서는 `impact_note` 필드에 이 3단을 담는다.

## 2. 표현 규칙 (Phase 6 하드 제약과 동일)

- **단정 금지 · 확률 표현 강제** — "~할 가능성", "~로 추정", "~와 정합". 인과 단정("~때문에") 금지.
- **선행/후행 판정 금지** — 지표 간 선·후행 관계를 단정하지 않는다(상관/정합만).
- **임의 수치 금지** — 입력 스냅샷에 없는 수치를 만들지 않는다. 근거(`basis`)는 실제 지표·수치만.

## 3. 전망 본문 구조

`statement`는 **현상 → 원인 → 배경 → 전망** 흐름을 자연스러운 산문으로 담는다(라벨형 소제목·H2 금지).

## 4. 판정 가능성 (트래킹 전제)

모든 전망은 사후 판정이 가능해야 한다.

- `horizon_date` — 판정 기준일
- `metric_ref` — 판정에 쓸 실측 지표 참조 (예: `KCCI`, `SCFI`, `delay_index_weekly:<lane_id>`)
- `invalidation_condition` — 전망을 무효화하는 사전 명시 조건 (예: 해협 재개방)

## 5. 검수·발행 흐름

생성 산출물은 전부 `status='draft'`로 적재된다. **에디터 검수 후에만 published**. 발행 후 본문 수정·삭제 불가(무효 조건만 예외). 적중률은 published 전수 기준으로 계산하며 표본에서 빼지 않는다.
