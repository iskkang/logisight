# Analysis Doctrine (Logisight)

분석 *방법*의 기준. 문체·형식은 `report/MONTHLY_REPORT_STYLE.md`(표현)가, 작성 공통 규칙은 `REPORT_AUTHORING_STANDARD.md`가 담당한다. 이 문서는 **어떻게 분석·사고하나**(사고)를 정의하며, `report/generate-monthly-analysis.js` 시스템 프롬프트가 이를 구현한다.

## 0. 포지셔닝 (대전제)

Logisight는 **인텔리전스** 리포트다(어드바이저/포워더 리포트가 아님).
- 권한의 원천 = **중립적 정확성**. "이렇게 돌아가고, 운명은 Y가 가른다"를 말한다.
- 화주에게 특정 행동(부킹·계약)을 **처방하지 않는다**. 처방은 객관성(=유일한 차별화)을 훼손한다.
- 루프를 닫는 방식 = 권고가 아니라 **"무엇을 주시하고 왜 중요한지"**. 처방 0, 좌표 제공.

## 1. 인사이트 7동작 (분석 깊이의 정의)

서술("올랐다")을 넘어 아래 동작으로 깊이를 만든다. 데이터가 뒷받침하는 것만, 억지 금지.

1. **컨센서스 해체** — 지배적 서사(예: 단일 지정학 변수)로 설명 안 되는 부분을 찾는다. 동인 분해(공급 충격 vs 수요 선행/풀포워드).
2. **이상치 추적** — 통합 서사에 안 맞는 지표 발산을 쫓는다(동일 충격인데 항로·지수별 방향 상반 등).
3. **2차 효과·메커니즘** — 전달 경로와 끊기는 지점(예: 벙커 조정 전 선적 전진 → 데드라인 후 수요 공백).
4. **베이스레이트·역사 유추** — 과거 유사 충격의 피크→정상화 소요·되돌림 폭. "이번엔 같다/다르다"를 근거로.
5. **리스크 비대칭** — 이미 가격에 반영된 것 vs 아닌 것 → 상·하방 어느 쪽이 비대칭인가.
6. **도메인 연결** — 사일로 금지. 벙커유→운임 floor→항공 전환 수요→항공운임 등 한 사슬로.
7. **스윙 변수 + 관측 시그널** — 국면을 가르는 단일 변수와, 그 향방이 *먼저* 드러나는 관측 가능한 신호. (= 처방 없는 actionability의 정답.)

## 2. 규율 (깊이 ≠ 추측)

인텔리전스에서 근거 없는 자신감은 얕음보다 나쁘다(평판 직격). 깊이는 규율 위에서만 성립한다.

- **그라운딩** — 모든 인사이트는 입력 사실·수치에 못 박거나, 넘으면 `[Logisight 분석] + (추정)` 표기. 수치는 공급된 `[지표 수치 & 발산]` 블록(Supabase `freight_indices`)의 값만. 임의 수치 생성 금지.
- **수치 스캐폴딩** — #1·#2(분해·이상치)는 *계산된 숫자*가 있어야 가능. 파이프라인이 WoW/MoM/QoQ·발산을 미리 계산해 프롬프트에 주입한다(`buildIndexFeatures()`).
- **시나리오 우선** — 점예측보다 조건부·시나리오. 단정 금지.
- **반증 가능** — 전망은 `horizon_date·metric_ref·invalidation_condition`로 사후 판정 가능해야 한다. `invalidation_condition`은 #7 스윙 변수의 트래킹 형태.

## 3. 구현 위치

- 시스템 프롬프트 규칙 ④ (`generate-monthly-analysis.js`) = 인사이트 7동작 중 1개를 ☞로 마무리.
- 데이터 원칙 #8 = 단일 변수 환원 금지(동인 분해 강제).
- `buildIndexFeatures()` = 수치 스캐폴딩(발산 자동 적시).
- `REPORT_AUTHORING_STANDARD.md` §1 = 처방 금지·의사결정 함의.

## 4. 적용 범위 (현재 / 후속)

- **현재 적용:** 월간 총론·항로별 등락·심층 기사(`generate-monthly-analysis.js`).
- **후속(미적용):** 02-x 지표별 코멘트(섹션 러너), 항공·철도 섹션, 주간 CADI. 동일 도크트린을 확장 예정.
